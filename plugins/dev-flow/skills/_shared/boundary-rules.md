# 邊界判斷規則

`_shared/conventions.md` 的分片。**設計與實作 skill 動手前先讀這份**(`/system-design`、`/subsys-design`、`/feature-design`、`/enhance-design`、`/feature-impl`、`/enhance-impl`、`/bugfix`)。前三節共用;「設計階段」只有設計 skill 用,「實作階段」只有實作 skill 用。測試怎麼寫在 `testing-policy.md`,只有真的要動測試的角色才讀。

## 知識歸屬

系統裡每一個事實,只能有一個地方知道它。

判準:**「這件事以後要改,我們希望只改一個地方,那個地方是哪裡?」** 答案出來後,這個事實只能住在那裡;其他模組需要它,透過介面問,不准自己抄一份。

## 層級判斷:這個問題歸誰決定

看答案會不會出現在模組邊界上:

- 只活在函式/模組內部,外面看不到 → **實作層級**,你自己決定,不要問
- 會改變模組之間的依賴、對外介面、或未來修改的代價 → **架構層級**,必須問開發者

等價判準:「這個決定做錯了,改回來要不要驚動其他模組?」不用 → 自己決定;要 → 問。

層級**不看技術含量,看影響半徑**:「用 String 還是 Text」在模組內部是實作問題;同一個問題出現在 public API 或 FFI 邊界上,就是架構問題。

## 發問協議

問開發者任何問題前,必須完成:

1. 搜尋 codebase 中相關的既有實作與慣例(專案有程式碼知識圖時可用它加速定位)
2. 讀過 invariants / ADR / 本檔,確認答案不是已經被決定過
3. 確認這是架構層級的問題(見上)

發問格式:

- **背景**:在做什麼、為何卡住(2 句內)
- **已查過**:看了哪些檔案/文件,發現什麼
- **選項**:2-3 個,每個附「當下成本」與「三個月後的代價」
- **我的傾向**:選哪個、為什麼、此決定是否可逆

禁止問可以自己查到答案的問題;禁止問實作層級的問題。委派模式下一律不得提問,改記「待確認假設」(見 `delegation.md`)。

## 設計階段規則(設計 skill 適用)

每個新增或修改的元件,設計文檔要明確回答四件事:

1. **擁有的知識**:它是哪些事實的唯一真相來源
2. **依賴方向**:依賴誰、誰依賴它;**新增的依賴邊單獨標註**
3. **不可逆決定**:存檔格式、對外 API、FFI 邊界、資料 schema——每條附至少一個被否決的替代方案與否決理由(重大者升級為 ADR)
4. **公開介面可測性**:怎麼只從公開介面測它。設計階段就要回答,不准留到實作時開後門。走 spec 驅動流程時這條有硬性判準:**每條介面至少被一條 Law 或一個 Example 覆蓋**,覆蓋不到就是介面設計缺陷,回頭修介面

**設計階段可以碰程式碼,但只能碰骨架**(`spec-roles.md`):型別定義、函數簽名、模組匯出清單寫完整,函數本體一律未實作標記。寫進任何一行實作邏輯就是越界——那是實作階段的自主權範圍。

**每個「建議」的義務**:凡標「建議」的選項,必須同時寫出它省了什麼(當下成本)、付了什麼(三個月後的代價、被綁死的選項)、有沒有觸碰任何 invariant。只寫得出好處、寫不出代價的建議 = 分析不完整,重做。

**完成定義**:開發者能用兩句話向第三者說明「這個改動動了系統的哪個部分、為什麼」。文件以此為目標書寫,不以完整羅列細節為目標。

## 實作階段規則(實作 skill 適用)

動手前先讀本檔與該任務的設計文檔。

- **範圍紀律**:只實作設計文檔裡有的東西。實作中發現設計沒涵蓋的情況——屬實作層級 → 自己決定,記進「實作備註」與 PR 描述;屬架構層級 → **停下來**按發問協議發問,不准先寫再說
- **禁止「順便」**:順便重構、順便加功能、順便改介面,一律不做。發現值得做的事記成清單回報,由開發者決定要不要開新任務
- **依賴檢查(每次提交前自查)**:本次改動有沒有新增任何 import 方向?有 → 對照設計文檔,文件裡沒有這條邊就是架構變更,停下來發問。核心層有沒有出現表現層/前端/測試的概念?有 → 移除
- **測試**:走 spec 驅動流程時(`/feature-impl`、`/enhance-impl`)**你不寫測試也不讀測試**,測試是 qa 的產出——只跑,紅燈照 `spec-roles.md`「仲裁協議」歸因。`/bugfix` 走單角色,自己寫重現測試,遵守 `testing-policy.md`;「不開後門就測不到」一律視為介面設計缺陷回報
- **PR 描述**:用「改了系統的哪個部分、為什麼」描述,不用檔案清單(格式見 `/branch-pr`)
