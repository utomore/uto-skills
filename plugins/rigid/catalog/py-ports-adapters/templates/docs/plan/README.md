# 開發計畫

需求依**實際的開發順序**切成可開發單元。里程碑是我們自己的開發順序，每個里程碑結束時展示得出一件事。

## 怎麼讀

- 做一個單元：讀這份 README 與那個里程碑的檔案就夠了，不必讀其他里程碑。
- 找一個單元：`grep -rn "REQ-019" docs/plan`。
- 看進度：`make progress`，或 `make progress M=M3` 列出 M3 的每一個單元與它有證據的驗收條數。

## 可開發單元

- **一個單元是一個垂直切片**：有入口（畫面、API、CLI 或基礎設施），合併之後就展示得出來，不必等別的單元。
- **大小是一個人一到五個工作天。** 超過就拆；拆不開的寫明原因。
- **依賴只指向同一個或更早的里程碑。** 需要後面才有的東西的規則，放到那個東西出現的單元，不寫在前面。
- **驗收寫成檢查得了的句子**，可以用 `docs/glossary.md` 的名詞；不做超過能驗證的承諾（不寫「保證正確」，寫「數字等於直接執行那段查詢的結果」）。
- **單元句用那個角色聽得懂的話**；技術基礎的單元可以直接講技術。

每個里程碑檔案的第一張表是它的單元，欄位：

- `id`：`REQ-<三位數>`，依開發順序編，不重複、不重用。
- `單元`：一句話。
- `domains`：由哪裡實作，以逗號分隔。可以填領域名、`platform`、`app`、`infra`；還沒有領域的填 `-`。`scripts/check_laws.py` 會檢查列出的領域都有資料夾。
- `依賴`：要先完成的單元。

每個單元的驗收寫在表格下方的 `## REQ-xxx`，一條一行，以 `- ` 開頭。

## 完成

一個單元完成，是它的每一條驗收都有證據（ADR-006）。做完一條，就在那一行行尾寫「（證據：a、b）」：

| 證據 | 寫法 | 用在 |
|---|---|---|
| law | `law:<領域>/LAW-3` | 領域的規則 |
| 測試 | `test:tests/platform/test_settings.py::test_missing_settings_are_all_named` | platform、api、cli 的行為 |
| 管線的步驟 | `ci:unit` | CI 裡每次都會跑的步驟 |
| 檢查腳本 | `check:check_errors` | `make check` 跑的腳本 |
| 展示 | `展示:部署dev` | 只能由人在測試環境看的；看過之後在里程碑檔最後的「## 展示紀錄」記一列，「展示」欄寫 `REQ-003/部署dev`，依據寫得出查得到的東西 |

一條驗收寫了幾項證據，每一項都成立才算有證據。`make check` 會檢查證據都找得到。一條驗收寫不出證據，就是還沒做，或是寫得檢查不了，後者要改寫驗收。
