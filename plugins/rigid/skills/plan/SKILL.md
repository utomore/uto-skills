# rigid:plan — 開發計畫

> **核心**：A unit is a vertical slice one person finishes in one to five days, its acceptance is a sentence something can prove, and its order comes from dependency alone.（一個單元是一個人一到五天做完的垂直切片，驗收是一句有東西能證明的話，順序只來自依賴。）步驟與這一句衝突時，這一句贏：停下，回報。

## 輸入 / 產出

| 輸入 | 產出 |
|---|---|
| 架構師講的需求；`docs/plan/README.md`、既有的 `docs/plan/M*.md`、`docs/glossary.md`、`docs/adr/` | `docs/plan/M<n>-<slug>.md`（單元表與每個單元的驗收行）、`docs/plan/README.md` 的驗收情境、里程碑表與「為什麼是這個順序」、`docs/glossary.md` 新登記的名詞（識別名 `-`）；`make check` 綠 |

## 分流

- 沒有 `scripts/_layout.py` → 框架還沒鋪，先走 `rigid:scaffold`。
- 要改的是框架本身（加一層、加檢查、換 CI）→ `rigid:scaffold`。
- 架構師要的是「這個單元做完了沒」→ 那是 `make progress` 的事，不用談；狀態由驗收行尾的證據推算，這裡不填狀態。

## 步驟

1. **看現況。** 讀 `docs/plan/README.md` 與每份 `M*.md`，記下已經用掉的 `REQ` 號與每個里程碑的出口條件；讀名詞表。有單元已經寫了證據的里程碑，它的單元句與驗收不重寫，只能加。
2. **驗收情境先講**（第一次才做）：對客戶或使用者最後要展示什麼，一條一句寫進 README「## 驗收」。它是終點，不是計畫。
3. **一次一條需求，一題一題問**：
   - **單元句**：用那個角色聽得懂的話一句話講，例「管理員設定角色，並把角色指派給使用者」；技術基礎的單元可以直接講技術。
   - **大小**：一個人一到五個工作天、合併之後就展示得出來。超過就當場拆成幾個單元，各自有入口；拆不開的在單元底下寫明原因。
   - **依賴**：要先有什麼才做得了。只准指向同一個或更早的里程碑；需要後面才有的東西的規則，放到那個東西出現的單元，不寫在前面。
   - **domains**：由哪裡實作。既有的領域填識別名；還沒有領域的填 `-`，並在下一題登記名詞；platform、app、infra 直接填。不在這裡建領域、不在這裡定識別名。
   - **名詞**：單元句與驗收裡出現的領域名詞，一個一個問「它是什麼、不是什麼」，一句話寫進 `docs/glossary.md`，識別名填 `-`（實作的人決定）。之後程式碼裡只准用登記過的識別名。
   - **驗收**：一條一行，以 `- ` 開頭，寫成檢查得了的句子：不寫「保證正確」，寫「數字等於直接執行那段查詢的結果」；不寫「操作順暢」，寫「按下送出三秒內看到訂單編號」。每一條都要答得出「將來用什麼證明」（law、測試、CI 步驟、檢查腳本、展示），答不出來就改寫。**行尾不寫證據**，證據由做單元的人做完才寫。
   - **領域怎麼用**（選填）：架構師講得出實作的走法（哪個 use case、接哪個 port、哪個既有領域的函數）就寫一段在 `## REQ-xxx` 開頭，給做的人看；講不出來就不寫，不猜。
4. **編號與落檔**：`REQ-<三位數>` 依開發順序編，不重複、不重用；寫進里程碑檔的單元表（`id`、`單元`、`domains`、`依賴`）與表下方的 `## REQ-xxx`。里程碑檔的開頭是 `- 階段：`、`- 目標：`、`- 出口條件：`（結束時展示得出的那一件事）。新的里程碑要在 README 的里程碑表加一列，並在「為什麼是這個順序」補一句：它依賴什麼、誰依賴它。
5. **`make check`**：`check_laws` 會擋 id 重複、格式不對、domains 欄列了沒有資料夾的名字；`check_evidence` 會擋寫壞的證據行。紅的就改計畫，不改檢查。
6. **重排與改動**：架構師要改順序、拆單元、改驗收，照同一套問；已經有證據的驗收行不刪，要改就在旁邊加新的一行、舊的一行由架構師決定去留。號不重編。

## 收尾

回報這次新增或改動的每個單元一列（id、單元句、里程碑、domains、驗收條數）、登記了哪幾個名詞、README 改了哪幾段、`make check` 的結果。建議以 `plan/<slug>` 分支發 PR。接著做第一個單元不需要 skill：做的人讀 `CLAUDE.md` 與那一份里程碑檔就開工，做完在驗收行尾寫證據。

## 邊界

不寫證據、不記展示紀錄（做單元的人寫）；不建領域資料夾、不定識別名、不寫任何程式碼；不替架構師決定單元句、驗收與順序；不填狀態欄（沒有這種欄，狀態由 `make progress` 算）；不改框架、不改檢查腳本；不動已經有證據的驗收行。
