# 圖形詞彙表(共用)

投影片裡的圖形一律是 `talk/assets/` 底下的 SVG。本表是四件事的共同語言:`/section-design` **選型**(這頁需要圖嗎、哪一種)、`/section-impl` **繪製**、`/page-adjust` **調整**、`/review` **判讀**。

**分工**:選哪一種類型、這張圖回答什麼問題 → 設計層決定;怎麼畫(座標、配色、節點擺放、線怎麼走)→ **實作層自主決定**,設計文件不預先指定畫法。

**一張圖回答一個問題**。畫完自問這張圖回答的問題是什麼,答不出來就回設計文件;不需要圖硬配圖是 AI 感的頭號來源。

## 圖形類型選型表

| 圖形類型 | 適用 |
|---|---|
| 架構圖 | 系統元件與依賴關係 |
| 流程圖 | 步驟、判斷分支、資料流 |
| 結構圖 | 組成關係、樹狀階層 |
| 幾何圖 | 抽象概念的空間隱喻(集合、交疊、距離) |
| 包裹圖 | 內外包覆關係(容器、封裝、作用域) |
| 分層圖 | 上下堆疊的層次(協定棧、抽象層) |
| 金字塔圖 | 有數量或重要性梯度的層級 |
| 時間軸圖 | 演進、里程碑、版本歷程 |
| 象限圖 | 兩個維度的定位與取捨 |
| 循環圖 | 迴圈、回饋、生命週期 |
| 對比圖 | before/after、方案 A/B 並排 |
| 漏斗圖 | 逐階段收斂或流失 |
| 網絡圖 | 多對多關係、拓撲 |
| 資料圖表 | 有真實數據時的長條/折線/圓餅 |
| 截圖加註圖 | 實際產品畫面、操作導覽 — 使用者提供截圖或參考圖時,以該圖為底疊加編號標記,不重畫 |

可組合,也可提出表外類型(提出時在設計文件寫明它回答什麼問題)。

## 圖形紀律(實作與審查的共同底線)

| 項目 | 準則 | review 的扣分線 |
|---|---|---|
| 連接線轉折 | ≤2 折 | 3 折起扣;≥4 折重扣 |
| 交叉 | 0(不得已用跨線符號) | 交叉成網重扣 |
| 流向 | 同一張圖單一主方向 | 看不出流向重扣 |
| 標籤 | 貼近所指(<20px),不壓線 | — |
| 節點數 | ≤7(超過就分層或拆圖) | — |
| 文字 | 用 `<text>`,不轉曲線 | — |
| 外部資源 | 禁止(網路圖片、CDN 字型)— 離線必須可用 | 阻斷項 |

- **配色只用 `theme.css` tokens 的色值**(手抄具體色碼,同一張圖內保持一致);字體與投影片同 família。圖裡不自創色票 — 要新色就回 `/topic-design` 加進 tokens
- **連接線方向順著該頁動線**:線把眼睛帶向重點,不拉回頭、不指向頁面外

## 尺寸與嵌入

- viewBox 依內容比例自訂(不必 16:9),但**先想好嵌入格的大小**
- 圖內文字在**版面上的最終渲染大小**不得小於約 18px — 嵌入格會縮放,畫圖時要回推名目字級
- 以 `![h:400](../assets/diagram-XX-N-<slug>.svg)` 限高或 `![w:560](...)` 限寬嵌入指定格;放哪一格由該頁的重點決定(圖是主角就給大格或整頁 `center`)
- 檔名與 metadata 規範見 `conventions.md`(**XML 註解裡不得出現連續兩個減號**,會讓整張 SVG 變成無效 XML)

## 幾何靠量測不靠目視

標籤有沒有溢出、連線端點有沒有貼齊、線有沒有穿過節點、尺寸間距是否一致 —— 這些讀原始碼猜不出來,用 `/svg-layout` 取得數字:

```
normalize → inspect → 改 → lint
```

畫完先跑一輪把 error 修掉再往下;review 目視存疑時也回到 lint 拿量化證據(溢出幾 px、端點間隙幾 px、幾折),報告要指得出數字。

## 截圖加註圖

使用者提供截圖或參考圖時,**先問是否直接用截圖加註**(以原圖為底疊編號標記)—— 最忠實也最省工,不合適再重畫。

- 原始圖檔存 `talk/assets/img-<section編號>-<段內序號>-<slug>.<ext>`(保留備改);加註 SVG 照 diagram 的命名與 metadata
- **截圖必須以 base64 data URI 內嵌**進 SVG 的 `<image>` —— SVG 經 `<img>` 載入時讀不到外部檔案,外連路徑會整張空白
- viewBox 取截圖原始像素比例
- 標記用**編號圓徽**(1、2、3…)貼在目標區域旁,必要時加框線圈出區域或短箭頭指向;色值用 tokens 的強調/主色,徽章字體與投影片同 família
- 標記 **≤5**,且**編號順序 = 本頁動線順序**(聽眾照號碼走一遍就看完);超過 5 個就拆頁
- **說明文字不寫進圖裡** —— 放頁面內文作圖例(慣用格局見 `layouts.md`:圖佔大格,下方並列格每格「編號 + 短標 + 一行說明」),文字遵守文字規範,與標記**一一對應、缺一即錯**
- 連接線折數規則對此類圖不適用,改看標記與圖例的對應與縮放後可讀性

## 風格基底 → 圖形風格

`topic.md` 的 `style-base`(見 `styles.md`)決定圖形的表現傾向;偏離要記進「投影片風格」章節:

| 基底 | 圖形傾向 | review 從嚴之處 |
|---|---|---|
| `tech-deep` | **精確派** — 方框直角、連接線正交(水平/垂直)、對齊格線;元件用真實名稱(服務名、port、版本號),不用示意代稱;圖例與方向標明確 | 不精確(斜線亂連、未對齊) |
| `keynote-impact` | **示意派** — 圓角、留白、隱喻圖形(幾何/包裹/金字塔);細節省略,一張圖只留一個對比或一個關係;數據圖只標關鍵數字 | 圖上塞進細節、失去單一訊息 |
| `intro-friendly` | **比喻先行** — 幾何/包裹/循環圖優先於架構圖;真實架構要出現時先給簡化版 | 節點 ≤5 從嚴;術語未附白話對照 |
| `workshop-guide` | **截圖優先** — 截圖加註優先於手繪圖,標記編號 = 操作順序;架構圖只在「為什麼這樣做」的頁面出現且保持簡化 | 截圖縮放後可讀性、標記與圖例對應 |
| `exec-brief` | **資料優先** — 有真實數據就畫資料圖表,軸與單位必標、註明來源與期間;架構圖只在解釋因果時出現 | 假數據訊號(無單位、整數湊數、無來源);裝飾性圖形視為離群 |
