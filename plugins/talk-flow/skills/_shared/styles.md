# 風格基底詞彙表(共用)

不同場合的簡報有不同的視覺語言。`/topic-design` 訪談時從本表選定一個**風格基底**(記入 `topic.md` frontmatter 的 `style-base` 與「投影片風格」章節),它為版面、配色、**分層(背景)**、文字規範、圖形風格與節奏提供**預設值** — 之後 theme.css tokens 怎麼調、文字規範怎麼填、section-impl 排版怎麼選、review 怎麼判「收斂 vs 失控」,都以選定的基底為準。

基底是**預設值不是枷鎖**:訪談可逐項細調,但偏離基底的決定要寫進 `topic.md`「投影片風格」章節,不留口頭默契。五個基底都不合適時用 `custom`,並把等值的規格(版面、配色、分層、文字、圖形、節奏六項)完整寫進「投影片風格」與「投影片分層」。

**本表給的是起始區間,不是記錄值**:本演講最後採用的 px、色碼、opacity 一律只住在 `talk/src/theme.css`(唯一真相)。本表的建議值是調 tokens 時的起點,`topic.md` 記錄的是**語意與理由**(哪個級別用在哪、背景幾套各代表什麼),不複製一份數值。

各節的顆粒度:「分層」給的是**背景的預設方向**(要不要背景、幾套、多強),詞彙與 tokens 見 `layers.md`;「版面」對應的版型類別見 `layouts.md`;各基底的**圖形風格**見 `diagrams.md` 的「風格基底 → 圖形風格」表,本檔不重複。

| 基底 | 一句話 | 對應 event-type(預設推薦) |
|---|---|---|
| `tech-deep` | 精確、收斂、資訊可查證 | deep-tech、internal(技術題)、lecture |
| `keynote-impact` | 一頁一擊,視覺是論點的放大器 | keynote、lightning |
| `intro-friendly` | 低門檻、比喻先行、留白多 | intro |
| `workshop-guide` | 跟著做:步驟、截圖、可操作 | workshop |
| `exec-brief` | 結論先行、數據撐腰、快進快出 | internal(匯報題) |

## tech-deep 深度技術風

- **版面**:標題固定左上(theme 預設 h2),每頁位置不動;版型高度收斂 — 同類內容全場同版型,以 `cols-2` / `cols-1-2` / `rows-2` 為主力;`center` 只留給關鍵結論(全場 ≤3 頁);資訊密度中高,但仍守一頁一重點
- **配色**:低飽和、雙色以內;主色沉穩(藍/灰藍系),`--c-accent` 對比明確但不螢光;深淺色皆可,程式碼區塊底色要與正文區分
- **分層**:背景要嘛不用(`none`),要用就克制到幾乎察覺不到 — 單側色帶或細格線,`--bg-opacity` 0.25–0.4,全場一套;程式碼頁、架構圖頁、表格頁一律 `bg-none`
- **文字規範預設**:強調以**粗體**為主(術語首現),`accent` 只給關鍵數字/警示;列表圓點為主、步驟才編號;字級全用 theme 預設,不放大取寵
- **圖形**:精確派(見 `diagrams.md`)
- **節奏**:divider 每 section 一張;每頁 60–180 秒,允許聽眾逐格讀完
- **review 提示**:版型語彙變異在此基底從嚴;大字置中頁連續出現反而算離群;背景看得出圖案、或用了兩套以上背景,在此基底算離群

## keynote-impact 主題演講/行銷風

- **版面**:freestyle — 大字置中頁(`center`)是主力,一頁一句話、一個數字、一張大圖;標題本身可以是視覺主角(大、粗、佔畫面);grid 切格頁是配角,密度低
- **配色**:高對比、敢用色 — `--c-accent` 飽和搶眼(用在要讓全場記住的那句話/那個數字),深色底 + 亮色字是常見選擇;但仍只住 tokens,搶眼 ≠ 每頁換色
- **分層**:背景是主力之一 — 大面積色塊/漸層/照片,`--bg-opacity` 0.5–0.8;可用到 2–3 套(封面與 divider 一套、內容頁一套),但每一套要對應到演講結構;照片背景務必配 `plate` 或壓到 0.3 以下,字讀不清就是失敗
- **文字規範預設**:強調以 `accent` 大字為主;正文字級整體偏大(theme tokens 上調);列表少用 — 超過 3 點就該拆成 3 頁;結論句可獨佔一頁置中
- **圖形**:示意派(見 `diagrams.md`)
- **節奏**:翻頁快,每頁 20–60 秒;divider 可省略(用 center 大字頁自然轉場);頁數多但每頁輕
- **review 提示**:center 頁佔比高、版型多變、背景強烈**不算失控**(這是基底特性);但「搶眼」失控的訊號要抓 — accent 一頁多處、每頁都在喊重點等於沒有重點;逐字塞滿的 center 頁從嚴;背景搶走第一眼、或背景換得對不上演講結構(逐頁亂換)照樣扣

## intro-friendly 科普啟蒙風

- **版面**:留白多、密度低 — 每頁最多 3 個資訊塊;`cols-2`(比喻圖 + 一句白話)與 `center` 為主;標題用問句或白話,不用術語
- **配色**:明亮溫和、飽和度中等;淺色底為預設;`accent` 用於「原來如此」的那個點
- **分層**:柔和有機色塊(如 `bg-blobs`)是預設,`--bg-opacity` 0.4–0.6,走對角、中央留白 — 背景讓畫面親切不空,留白多才是重點;全場一套即可,比喻圖與截圖頁 `bg-none`
- **文字規範預設**:字級整體偏大(theme tokens 上調);強調以粗體 + accent 並用但每頁仍只一處;列表圓點、每點不超過一行;術語首現必附白話對照
- **圖形**:比喻先行(見 `diagrams.md`)
- **節奏**:每頁 40–90 秒;新概念之間要有喘息頁(複習、比喻、提問);divider 用來標「我們走到哪了」
- **review 提示**:每分鐘新概念數的峰值判準從嚴(聽眾先備少);術語未附白話對照在此基底加重扣

## workshop-guide 工作坊教學風

- **版面**:步驟導向 — 編號列表與**截圖加註圖**是主力;`rows-2`(上截圖下步驟)與 `cols-1-2`(左步驟右截圖)為慣用格局;每頁對應一個可操作動作
- **配色**:功能性配色 — `accent` 固定語意「現在要按/要改的地方」,全場不換義;程式碼區塊佔比高,底色與字級優先照顧可讀性
- **分層**:背景只做「我現在在哪個階段」的識別 — 極淡格線或底部色帶(`--bg-opacity` ≤0.35),最多兩套(操作頁一套、檢查點頁一套);**截圖頁與程式碼頁一律 `bg-none`**,背景疊在截圖底下只會讓人看錯
- **文字規範預設**:列表以**編號為主**(操作有順序),圓點只用於注意事項;強調用 `accent` 指向操作目標、粗體標指令與檔名;等寬字體使用頻繁,`--f-mono` 要挑清楚的
- **圖形**:截圖優先(見 `diagrams.md`)
- **節奏**:每頁停留看操作長短(30 秒–3 分鐘都合理);檢查點頁(「你現在應該看到…」)定期出現;divider 標記練習階段
- **review 提示**:時間帳判準放寬(操作時間難估,緩衝留 15–20%);缺檢查點頁列入建議

## exec-brief 內部匯報風

- **版面**:結論先行 — 第一頁就是答案,標題直接寫結論句(「Q3 延遲主因是 DB 連線池」而非「效能分析」);表格與數據頁佔比高,`rows-2`(上結論下證據)與表格頁為主力
- **配色**:樸素克制、印表機友善(淺色底);`accent` 固定語意(紅/橙 = 風險、綠 = 達標之類),全場不換義
- **分層**:預設 `--bg-image: none` — 印出來會變髒、數據頁會被干擾;真要有識別就只放一條公司色底帶(`--bg-opacity` ≤0.25),數據與表格頁 `bg-none`
- **文字規範預設**:標題全用結論句;強調以 accent 標數字與風險;列表圓點、每點含一個事實或一個行動;禁裝飾性元素
- **圖形**:資料優先(見 `diagrams.md`)
- **節奏**:每頁 30–90 秒;頁數精簡(能一頁講完不用兩頁);divider 通常省略,附錄頁放深究材料
- **review 提示**:無資訊標題(「概述」「現況」)從嚴;看得見的背景裝飾視為離群
