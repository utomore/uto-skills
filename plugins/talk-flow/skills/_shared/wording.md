# 文案語感規範(共用)

投影片上的字是**給人掃讀的**,不是給人品味抑揚頓挫的。本檔定義所有 skill 產出文字時的**硬性禁區**與正面寫法,`/topic-design`、`/section-design`、`/section-impl`、`/page-adjust` 產文時一律遵守,`/review` 依此扣分。

**適用範圍**:投影片前景的每一個字(標題、副標、內文、表格、圖形標籤與圖說)、頁內備註,以及 `docs/` 文件裡**直接會變成頁面文案**的句子(主題與副標方案、內容要點的措辭、頁面規劃的「一句話重點」)。

**唯一例外**:使用者**明確指定**的措辭、引用他人原話(加引號並註明出處)、專有名詞、程式碼與截圖裡的原文。例外一律是使用者的決定,skill **不得自行產生**;刻意破例時記進該頁備註或 `topic.md`「文字規範」的「文案語感例外」。

## 核心原則:一句話只做一件事

要講就直接講事情。**要對比,就把對比交給版面** —— 左右分格、表格兩欄、✓/✗ 兩列、前後兩頁,都能承載對比;把對比塞進同一句話裡做否定再翻轉,是最典型的 AI 腔,投影片上只會讓人煩。

## 禁區一:對比翻轉句(一律不得產出)

**判準一句話:同一個句子裡出現「否定 + 轉折」就是命中。**

| 句型 | 爛範例 | 直接寫法 |
|---|---|---|
| 「A,不等於 B」 | 分不出差別,不等於一樣好 | 目前沒有證據說哪一版比較好 |
| 「是 A,不是 B」 | 是「還沒有證據說誰比較好」,不是「兩版一樣」 | 標題寫結論「證據不足,無法判定優劣」;兩種解讀要並陳就用兩列 ✓/✗ 承載 |
| 「不是 A,而是 B」 | 這不是效能問題,而是設計問題 | 根因在設計:連線池被共用 |
| 「不只是 A,更是 B」 | 這不只是工具,更是工作方式的改變 | 工作方式跟著改:從手動改設定變成一行指令 |
| 「不僅 A,還 B」 | 不僅省時間,還降低出錯率 | 省 3 小時/週,錯誤率從 8% 降到 1% |
| 「與其 A,不如 B」 | 與其猜,不如量 | 先量再改 |
| 「不在 A,而在 B」 | 重點不在工具,而在流程 | 瓶頸在流程:三個人排隊等同一次審核 |
| 「A 很重要,但 B 更重要」 | 速度很重要,但正確更重要 | 正確優先於速度 |
| 「不是不能 A,只是 B」 | 不是不能做,只是成本太高 | 成本太高:一次要 40 人天 |
| 破折號翻轉「A —— 其實是 B」 | 慢的是查詢 —— 其實是索引 | 索引沒建,查詢掃全表 |
| 英文同族 | Not a tool, but a workflow / It's not about speed, it's about correctness / Less config, more code | 直接寫結論句 |

同族的變形一律比照(「並非…而是…」「與其說 A,不如說 B」「表面上 A,實際上 B」「看似 A,其實 B」)。

## 禁區二:人稱指稱

投影片前景文字**不出現**「我」「我們」「你」「你們」「大家」「各位」「咱們」等人稱代名詞。台下已經知道是誰在講、講給誰聽,寫在投影片上不帶任何資訊,只是佔字。

| 爛範例 | 直接寫法 |
|---|---|
| 我們踩過的坑 | 這個專案踩過的坑 |
| 你需要注意三件事 | 三個注意事項 |
| 大家有沒有遇過這種狀況? | (要提問就把問題本身寫上去)部署完才發現設定沒同步? |
| 讓我們看看實際的數字 | 實際數字 |
| 你現在應該看到綠色的 OK | 畫面應該出現綠色 OK |

- 備註(presenter note)是寫給講者自己的**提醒**:一樣用名詞式短句(「先講 3 倍那個數字」),不要寫成口播詞(「我要告訴大家…」)。
- 圖形標籤同理:標角色與元件名(`使用者`、`API Gateway`),不寫「我方系統」。
- 互動提問頁真的需要對著台下問時,把**問題本身**寫上去就好,不需要「你」「大家」當主詞。

## 禁區三:其他 AI 腔

- **空泛詞**:賦能、助力、一站式、全方位、無縫整合、深度融合、極致、打造、閉環、抓手、顛覆、革命性、全新升級、下一代 —— 換成具體的動作、數字或名字
- **無資訊標題**:概述、總結、背景、簡介、關於 X —— 標題寫**這頁的結論或問題本身**(標題另有完整規則,見禁區四)
- **強迫排比**:什麼都湊成三點、每點字數修到一樣長、每頁都三張等寬卡片
- **膨脹副詞與贅語**:真正的、其實、關鍵在於、值得注意的是、不得不說、可以說是 —— 刪掉不影響意思就刪掉
- **修辭問句當標題**(「為什麼會這樣呢?」):除非這頁真的要停下來讓聽眾想
- **假數據**:100/200/300 的示意數字、沒有單位的軸、沒有來源的趨勢線

## 禁區四:標題是重點主軸,不是描述

標題是全頁第一眼,聽眾靠它決定這頁在講什麼。**一頁一個重點,一個標題一句話講完。**

三條判準,任一條命中就重寫標題(必要時拆頁):

1. **一句話講完**:標題是一個單句或一個名詞短語。**非必要不用逗號** —— 用逗號把兩件事串起來,就是這頁塞了兩個重點,該拆頁或該砍掉一半。專有名詞內含的標點、真正需要的並列頓號除外
2. **寫結論不寫描述**:標題說出這頁的結論或這頁要回答的問題。「這頁要介紹/說明/比較/分析什麼」是**描述**,屬於內文與備註,不是標題
3. **不放前提與過程**:條件、範圍限定、方法、步驟都是內文的事;標題只留結論

| 爛範例 | 為什麼爛 | 直接寫法 |
|---|---|---|
| 快取的三種取捨,以及最後怎麼選 | 逗號串兩件事 | 快取最後選了 write-through |
| 介紹 RAG 的檢索流程與常見失敗模式 | 在描述這頁要介紹什麼 | 檢索失敗八成出在切塊 |
| 部署流程說明 | 只報主題,沒說結論 | 部署卡在人工審核 |
| 效能問題的成因分析,以及優化後的數據 | 兩個重點塞一頁 | (拆兩頁)連線池被共用 / P99 從 1.2s 降到 180ms |
| 在資料量小於 10 萬筆時,索引不一定有用 | 前提寫進標題 | 10 萬筆以下索引沒有幫助 |
| 我們如何用 CI 把回歸測試自動化 | 描述句 + 人稱 | 回歸測試進 CI 後每次上線省 40 分鐘 |

**全簡報標題語法統一**:全部名詞短語,或全部結論句,由 `topic.md`「文字規範」拍板,不要混用。

## 正面寫法

- 標題 = 這頁的重點主軸,一句話講完(名詞短語或結論句,全簡報統一,見禁區四與 `topic.md`「文字規範」)
- 一行講完一件事;講不完就拆行、拆格、拆頁,不要靠句內轉折塞進去
- 有數字寫數字、有專案名寫專案名、有取捨寫取捨 —— 具體是去 AI 感最有效的手段
- 對比交給版面:兩欄、表格、✓/✗、前後兩頁

## 寫完自檢(每頁都跑一次)

1. 句子裡有沒有「不…而是/是/更/只是」的翻轉?有 → 改成直述句,對比移到版面
2. 有沒有人稱代名詞(我/我們/你/你們/大家/各位)?有 → 刪掉或換成具體主詞
3. 標題是不是一句話說出這頁的重點?有逗號串兩件事、或在描述這頁要講什麼 → 標題重寫,兩個重點就拆頁
4. 每個詞刪掉後意思會不會變?不會變 → 刪
5. 這句話換成任何一場演講都成立嗎?成立 → 太空泛,補上數字、專案名或取捨
