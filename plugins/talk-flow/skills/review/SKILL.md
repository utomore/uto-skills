# /review — 演講整體審查

先讀取 `../_shared/conventions.md`,遵守其中所有文檔慣例(metadata、頁碼同步、投影片規格)。

## 唯讀原則(不可違反)

本命令**只讀不寫**:不產出任何文檔、不修改任何檔案、不更新 metadata 的 `updated`、不「順手修一下」。
所有結論都以對話輸出。使用者要動手修時,導向對應命令:單頁 → `/page-adjust`、段落設計 → `/section-discuss`、講稿與 SVG → `/section-impl`、主軸或時間分配 → `/topic-design`。

## 範圍

- 無參數 → **全場審查**
- 參數是段落 id 或編號(`section-02`、`02`)→ **局部審查**:只審該段與其 `depends-on`、以及它與前後段的接縫;指標照算但在報告標明「局部,總分僅供該段參考」

## 前置

1. 執行機械檢查腳本(唯讀):

```
node <本 skill 目錄>/scripts/scan-coherence.mjs [專案根目錄,預設 .]
```

腳本交叉比對頁碼五處同步、段落覆蓋、先備知識順序、節奏(講稿字數對時)、銜接標記,並輸出**視覺規格逐頁表**(viewBox、字級、色票、漸層、字數、連接線數與最大轉折、溢出粗估、外部資源、emoji)、**全簡報色票與字體收斂度**、**各頁文字索引**。

2. 有「frontmatter 格式不合規」時**先停下**:清單欄位讀不到值,後面的比對全部不可信。請使用者(或經同意)改回行內陣列 `[a, b]` 再重跑。
3. 讀取 `docs/topic.md`(核心訊息、聽眾輪廓、投影片風格是所有判斷的基準)、全部非 rejected 的 `docs/section-*.md`、`talk/scripts.md` 全文。rejected 段落不讀。
4. **逐頁開 SVG,一頁都不能跳過**。腳本的表格只是證據與清單,不是替代品 — Layout、配色統一、用語一致、AI 感只能看;連接線折數腳本雖然算得出來,但「那條線是不是連接線」仍要開檔確認。局部審查時開該段所有頁,加上前後相鄰各一頁(判斷接縫)。
   - 可行時**用瀏覽器開 `talk/slide.html` 逐頁目視**(claude-in-chrome),這對 Layout 與 AI 感最準;同時讀 SVG 原始碼確認色值、字級、對齊座標
   - 不能用瀏覽器時,逐檔讀 SVG 原始碼判斷(座標與色值都在原始碼裡,只是要自己在腦中排版)
   - 頁數多時分批開,每批做完就把該批的逐頁檢視結果記下來,不要開完全部才開始判斷

## 判斷準則

### 偏題怎麼算

逐段標記四類,**偏題不是罪,量太多才是**:

- **貼題**:直接推進核心訊息
- **支援**:不直接推進但為後段鋪路(先備知識、動機、反例)
- **呼吸點**:刻意的幽默、故事、閒聊 — 服務節奏,**不計入偏題**
- **偏題**:對核心訊息無貢獻,也不服務節奏

偏題比例 = 偏題段落的 `est-minutes` 合計 ÷ 總時長。呼吸點超過 15% 時另計為節奏問題,不算偏題。

### 銜接怎麼評

每個接縫(段落接縫 = 段數 − 1;頁面接縫 = 頁數 − 1)評三級:

- **自然**:上一段/頁的結尾為下一個開場提供理由(問題被提出 → 下一段回答;概念被建立 → 下一頁使用)
- **可接受**:順序合理但沒有明說理由,聽眾要自己補
- **突兀**:主題硬切、需要尚未鋪陳的概念、或風格語彙突變

只列**突兀**與**可接受**的接縫並寫明理由;自然的只給數量。

### 峰值怎麼找

以「每分鐘新概念數」估段落難度(新概念 = 聽眾輪廓的「未知」清單裡的詞、或本段首次出現且需要解釋的術語)。峰值 = 明顯高於相鄰段落者。判斷三件事:

1. 峰值位置 — 落在演講 30–70% 處最好;全擠在最後 20%(疲勞區)最糟
2. 峰值是否連續 — 連續兩段高峰等於讓聽眾一路掉線
3. 峰後有沒有喘息 — 複習頁、圖解、呼吸點

### 逐頁看什麼(開檔時的五個面向)

**Layout**

- 對齊:標題基線、左邊界、卡片間距是否共用同一套網格;同類元素跨頁位置是否固定
- 層級:字級階層 3 級以內(標題/內文/備註),重點是否用大小或粗細分出來
- 留白:元素不頂邊(建議邊距 ≥60px)、間距一致、不擁擠
- 一頁一重點:能不能一句話說出這頁要幹什麼;說不出來就是該拆
- 動線:眼睛從哪看到哪;箭頭與標籤是否貼近所指物;有沒有需要來回跳的地方
- 硬錯誤:文字溢出、元素重疊、文字壓在圖形上看不清

**配色統一**

- 色票分類 ≤5 類(背景/文字/主色/輔色/強調),超過就是發散;用腳本的色票表當證據
- 強調色只在強調時出現(一頁最多一處);變成裝飾就失效
- 語意跨頁固定:同類元素同色,紅=問題、綠=正常不能中途換義
- 對比:正文對背景要看得清(淺色背景配淺灰字是最常見的失誤)
- 符合 `topic.md` 的 `slide-style` 與「投影片風格」章節 — 偏離要指出是哪一頁偏離、偏到哪去

**流程圖／架構圖(有圖的頁才評)**

- **連接線轉折 ≤2 折**:兩折是人眼能一眼追完的極限;**3 折以上就扣分**,要靠重排節點位置解決,不是把線繞過去
- 腳本的「連線/最大折」欄與 ✗/△ 已列出候選;開檔確認哪些是真的連接線(裝飾線、手繪風筆觸不算)
- 交叉線盡量為 0;非得交叉時用跨線符號,或換布局(分層、換邊)
- 流向一致:同一張圖只有一個主方向(左→右 或 上→下),不要一半向右一半向左
- 標籤貼近所屬線條(距離 <20px),不要讓聽眾猜哪個標籤配哪條線
- 節點數 ≤7:超過就分層或拆頁(這是聽眾一眼能數完的上限)
- 圖上的元件名稱與講稿、其他頁面用同一個名字(見下一節)

**用語與概念一致**

- 同一概念全場同名:`Folder` / 資料夾 / 目錄不能混用;投影片與講稿也要一致
- 中英夾雜規則一致:首次出現給全稱 + 縮寫,之後統一用縮寫
- 專有名詞大小寫正確且一致(BigQuery 不是 Bigquery / bigquery)
- 標題語法一致:全部名詞短語,或全部結論句,不要混
- 數字與單位格式一致(slot 數、金額、百分比的寫法)

**AI 感(具體訊號,不是感覺)**

- 樣板骨架:每頁都「標題 + 三顆等寬圓角卡片 + icon」,內容換了結構沒換
- 強迫對稱:什麼都湊成三點、每點字數幾乎一樣長 — 真實內容不會這麼整齊
- 無意義裝飾:漸層背景、光暈、與內容無關的幾何點綴或 icon
- Emoji 當項目符號
- 空泛語言:賦能、助力、一站式、全方位、無縫整合、顯著提升;形容詞多於名詞
- 無資訊標題:「概述」「總結」「關鍵要點」,而不是講出結論的句子
- 假數據:圖表軸沒單位、數字是 100/200/300、趨勢線沒有來源
- 沒有講者痕跡:沒有真實專案名、實際數字、踩過的坑、日期、取捨理由

反面證據(有人味):具體數字與專案名、明說的取捨、不對稱但有理由的版面、承認的失敗。判斷 AI 感時**先找反面證據**,找不到才扣分。

## 十一項指標(每項 0–5,總分 55)

| # | 指標 | 5 分 | 3 分 | 1 分 |
|---|---|---|---|---|
| 1 | **主軸貼合度** | 偏題 ≤10%,每段都說得出對核心訊息的貢獻 | 偏題 ≤25%,或有 1 段貢獻說不清 | 偏題 >35%,或核心訊息本身在講稿裡從未出現 |
| 2 | **結構完整度** | 開場鉤子、核心訊息明說、收束與行動呼籲三者都在 | 缺其中一項 | 缺兩項以上,或結尾停在最後一張技術頁 |
| 3 | **銜接自然度** | 無突兀接縫,可接受 ≤1 | 突兀 1–2 處 | 突兀 ≥3 處,或有段落接縫完全沒有理由 |
| 4 | **先備知識鋪陳** | 概念都在使用前被解釋,`depends-on` 與 order 一致 | 有 1 個概念用在解釋之前 | 順序倒置,或依賴 rejected 段落 |
| 5 | **講稿↔投影片一致度** | 無孤兒頁/幽靈標記;頁面文字與講稿說法、數字一致 | 有 1–2 處措辭或數字不一致 | 有孤兒頁,或投影片講 A 講稿講 B |
| 6 | **節奏與時間帳** | est 合計佔總時長 90–95%;講稿對時偏差 ≤15%;每頁 20–180 秒 | 偏差 ≤30%,或 1–2 段翻頁過快/停留過久 | 超出總時長,或講稿逐字照講會超時 |
| 7 | **認知負荷曲線** | 單一峰值落在中段且峰後有喘息 | 峰值偏後段,或峰後無喘息 | 多個連續峰值,或峰值全在最後 20% |
| 8 | **版面與配色一致度** | 共用網格與字級階層;色票 ≤5 類且語意固定;無溢出重疊 | 2–3 頁版面或用色離群 | 每頁自成一套,或有文字溢出/對比不足 |
| 9 | **用語與概念一致度** | 同概念全場同名,投影片與講稿一致,大小寫與縮寫規則一致 | 有 1–2 個概念換過名字 | 關鍵概念三種以上叫法,聽眾會以為是不同東西 |
| 10 | **去 AI 感／原創度** | 版面隨內容變化,有真實數字、專案名與取捨 | 有樣板痕跡但內容具體 | 樣板骨架 + 空泛語言 + 假數據,看不出誰講的 |
| 11 | **圖解可讀性** | 所有連接線 ≤2 折、無交叉、流向單一、標籤貼線、節點 ≤7 | 有 1–2 條 3 折線,或少量交叉 | 有 ≥4 折線、多條 3 折線、線條交叉成網,或看不出流向 |

第 11 項只在有流程圖/架構圖時計分;整場沒有圖就標「不適用」,總分改除以 50。

**符合度** = 總分 ÷ 55(無圖時 ÷ 50)。判定帶:

- **≥90%** 可以上台
- **75–89%** 小修即可上台(列出修哪幾處)
- **60–74%** 有結構問題,先修再排練
- **<60%** 回頭重整段落設計

**阻斷項**(命中就先修,分數再高也不放行):腳本有任何 ✗、先備知識順序倒置、孤兒頁、講稿對時超過總時長、核心訊息在講稿中從未出現、字級 <18px、引用外部資源(離線就掛)、文字溢出畫面。連接線轉折只計入第 11 項扣分,不列阻斷(腳本用 △ 標示)。

**流程阻斷**:有任何一頁沒開過就不准給第 8/9/10/11 項分數 — 改寫「未評(第 XX 頁未檢視)」,不要用腳本表格推測。

## 輸出格式(對話,不落檔)

```markdown
## 檢查範圍
(讀了哪些檔案、幾段幾頁、講稿字數;**逐頁開了哪幾頁、用瀏覽器還是讀原始碼**;局部審查要標明)

## 機械檢查
(腳本結果摘要:✗ 逐條列、△ 擇要;無 ✗ 就一句話帶過)

## 逐段評述
| Section | 分鐘 | 分類 | 對核心訊息的貢獻 / 問題 |
|---|---|---|---|
(分類 = 貼題 / 支援 / 呼吸點 / 偏題;偏題與呼吸點寫明理由)
偏題比例:X 分 / Y 分 = Z%

## 逐頁檢視(每一頁都要有一列,✓ 無問題 / △ 待確認 / ✗ 要修)
| 頁 | Section | Layout | 配色 | 圖解 | 用語 | AI感 | 具體問題(指得出元素、色值或線條座標) |
|---|---|---|---|---|---|---|---|
(圖解欄:無圖寫 -;有圖寫最大折數,如 `2折 ✓` / `5折 ✗`)

全簡報視覺一致性:色票分類與離群色、字體種類、跨頁版面語彙是否共用一套(引腳本色票表當證據)

## 接縫檢查
- 段落接縫:自然 N 處;可接受/突兀逐條列(哪兩段之間、為什麼、怎麼修)
- 頁面接縫:自然 N 處;可接受/突兀逐條列(哪兩頁之間、為什麼 — 含視覺語彙突變)

## 峰值地圖
(難度序列,如 section-01 低 → 02 高(峰)→ 03 中;峰值位置、是否連續、峰後有無喘息)

## 指標符合度
| # | 指標 | 分數 | 依據 |
|---|---|---|---|
總分 N/55 = XX% → <判定帶>(整場無圖則 N/50)

## 阻斷項
(命中的逐條列;無則寫「無」)

## 修正建議
(依優先序;每條標明用哪個命令、動哪個檔案、預期換來哪一項指標的提升)
```

## 紀律

- **證據優先**:每個扣分都要指得出檔案、段落、頁碼,視覺問題還要指得出元素或色值(「第 04 頁 #00ff88 只在這頁出現且不是強調」勝過「配色不統一」);講不出證據的扣分不要寫
- **沒看過不評**:逐頁檢視表缺哪一頁就寫「未檢視」,不要用腳本表格或檔名推測那頁長什麼樣
- **AI 感要留餘地**:先找反面證據(真實數字、專案名、取捨),找不到才扣分;風格偏好是使用者的,`topic.md` 允許的風格不算 AI 感
- **不腦補主軸**:核心訊息以 `docs/topic.md` 為準;覺得主軸本身有問題,寫進建議讓使用者決定,不要自己換一個主軸來評分
- **不重寫內容**:報告寫「哪裡不對、為什麼、建議往哪個方向」,不要在報告裡代寫講稿或 SVG
- 使用者反駁某項評分時,重新檢視證據:證據不足就下修結論,證據充足就把證據攤開,不要為了順從而改分
