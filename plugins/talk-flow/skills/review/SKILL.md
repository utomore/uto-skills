# /review — 演講整體審查

先讀取 `../_shared/conventions.md`、`../_shared/layouts.md`、`../_shared/styles.md`、`../_shared/layers.md`、`../_shared/diagrams.md` 與 `../_shared/wording.md`,遵守所有文檔慣例、版型詞彙、風格基底詞彙、分層詞彙、圖形詞彙與**文案語感規範**(它是本命令扣「文案語感」分數的唯一依據)。

## 唯讀原則(不可違反)

本命令**不修改任何原始碼、文檔與 metadata**、不「順手修一下」。只有兩個合法寫入:

1. **審查報告**:結論寫入 `review/review-<YYYY-MM-DD>-<序號>.md`(資料夾不存在就建立;序號 = 當日已有報告數 +1,從 1 起算),並在對話中給精簡摘要與報告路徑
2. **重新建置產物**:`talk/dist/` 與 `talk/src/slides.md` 是可再生成的**產物**,審查前執行 `node build.mjs` 重新建置不算違反唯讀(審過期產物才是錯的)

使用者要動手修時,**依層級**導向對應命令:單頁版面/圖形/背景類別/theme.css 數值 → `/page-adjust`;整段頁面與備註 → `/section-impl`;段落內容與圖形選型 → `/section-design`;主軸、時間分配、**視覺規範的語意**(文字規範增修、背景套數與用途、色票語意) → `/topic-design`。純數值問題(字太小、背景太濃)不要導向 `/topic-design` —— 那裡不記數值。

## 範圍

- 無參數 → **全場審查**
- 參數是段落 id 或編號(`section-02`、`02`)→ **局部審查**:只審該段與其 `depends-on`、以及它與前後段的接縫;指標照算但在報告標明「局部,總分僅供該段參考」

## 前置

1. 執行機械檢查腳本(唯讀):

```
node <本 skill 目錄>/scripts/scan-coherence.mjs [專案根目錄,預設 .]
```

腳本交叉比對段落覆蓋、頁數三處同步(deck 實際張數 / deck frontmatter / docs section)、圖形引用完整性、先備知識順序、時間帳與產物新鮮度,並輸出**頁面地圖**(版型、**背景類別**、內文形式、圖、備註字數、文字摘要)、**圖形 SVG 分析表**(viewBox、字級、色數、節點、連接線轉折)、**分層清單**(分層 tokens、背景與角標資產是否存在、頁面用到的 `bg-*` 類別分布)、**theme tokens 與寫死色值清單**,以及**文案語感命中清單**(對比翻轉句、人稱代名詞、空泛詞,以及**標題寫法**:逗號串兩件事、描述式標題、標題帶前提 —— 逐條給頁碼、位置與原句)。

腳本的文案語感清單是**證據不是判決**:每一條都要開檔確認是真的命中還是正則誤判(如「是不是」「不是…就是…」的並列;標題的逗號如果是專有名詞內含或必要的並列,也算誤判),確認為真的逐條計分,誤判在報告註明「已排除」。標題只掃得到形式,**「這個標題是不是這頁的重點主軸」要開頁自己判**——腳本沒命中不代表標題合格。

2. 有「frontmatter 格式不合規」時**先停下**:清單欄位讀不到值,後面的比對全部不可信。請使用者(或經同意)改回行內陣列 `[a, b]` 再重跑。
3. 讀取 `docs/topic.md`(核心訊息、聽眾輪廓、`style-base` 風格基底、投影片風格、**投影片分層**與**文字規範**是所有判斷的基準)、全部非 rejected 的 `docs/section-*.md`(含「規範外需求」是否都已回 topic 處理)、全部 `talk/src/section-*.md`(含備註)、`talk/src/theme.css`(視覺數值的唯一真相)。rejected 段落不讀。
4. **build 後逐頁目視,一頁都不能跳過**。腳本的表格只是證據與清單,不是替代品 — Layout、配色統一、用語一致、AI 感、圖形實際可讀性只能看:
   - 產物過期或缺席時先在 `talk/src/` 執行 `node build.mjs`(依 `topic.md` 的 `outputs`)
   - 可行時**用瀏覽器開 `talk/dist/slides.html` 逐頁目視**(claude-in-chrome),這對 Layout 與 AI 感最準;同時讀 `talk/src/` 原始碼確認版型類別、備註內容與圖形 SVG 的色值座標
   - 不能用瀏覽器時,逐檔讀 deck 原始碼 + 圖形 SVG 判斷(版型類別與圖形座標都在原始碼裡,要自己在腦中排版)
   - 局部審查時開該段所有頁,加上前後相鄰各一頁(判斷接縫);頁數多時分批開,每批做完就記下該批結果

## 判斷準則

### 層級紀律(文檔面,不計分但要列出)

視覺數值的唯一真相是 `theme.css`。逐條檢查並列進報告的「機械檢查」段:

- `docs/topic.md` 裡有沒有**寫死的視覺數值**(px 字級、色碼、`--bg-opacity` 的值)或 class 名(`bg-2`、`cols-2`)—— 有就是 L1 越權,而且必然與 theme.css 漂移,列出哪一節、值是多少、theme.css 的實際值是多少
- `docs/section-*.md` 裡有沒有指定版型類別、背景類別或圖形座標 —— 有就是 L2 越權
- 設計文件的「規範外需求」有沒有還沒回 `/topic-design` 處理就直接實作的
- 這些是**文檔一致性問題不是投影片問題**:不計入十四項指標,寫進修正建議即可(除非數值已經漂移到讓某項指標的判準失準,那要在該項註明基準以 theme.css 為準)

### 偏題怎麼算

逐段標記四類,**偏題不是罪,量太多才是**:

- **貼題**:直接推進核心訊息
- **支援**:不直接推進但為後段鋪路(先備知識、動機、反例)
- **呼吸點**:刻意的幽默、故事、閒聊 — 服務節奏,**不計入偏題**
- **偏題**:對核心訊息無貢獻,也不服務節奏

偏題比例 = 偏題段落的 `est-minutes` 合計 ÷ 總時長。呼吸點超過 15% 時另計為節奏問題,不算偏題。

### 銜接怎麼評

每個接縫(段落接縫 = 段數 − 1;頁面接縫 = 頁數 − 1)評三級:

- **自然**:上一段/頁的結尾為下一個開場提供理由(問題被提出 → 下一段回答;概念被建立 → 下一頁使用)
- **可接受**:順序合理但沒有明說理由,聽眾要自己補
- **突兀**:主題硬切、需要尚未鋪陳的概念、或版型/視覺語彙突變

段落接縫同時看備註的「銜接:」「交棒:」提醒是否對得上實際的前後頁內容。只列**突兀**與**可接受**的接縫並寫明理由;自然的只給數量。

### 峰值怎麼找

以「每分鐘新概念數」估段落難度(新概念 = 聽眾輪廓的「未知」清單裡的詞、或本段首次出現且需要解釋的術語)。峰值 = 明顯高於相鄰段落者。判斷三件事:

1. 峰值位置 — 落在演講 30–70% 處最好;全擠在最後 20%(疲勞區)最糟
2. 峰值是否連續 — 連續兩段高峰等於讓聽眾一路掉線
3. 峰後有沒有喘息 — 複習頁、圖解、呼吸點

### 逐頁看什麼(開頁時的十個面向)

九個面向的「收斂 vs 失控」都**以 `topic.md` 的風格基底為準**:`styles.md` 各基底附有「review 提示」— 同一現象在不同基底下判法不同(center 大字頁佔比高在 keynote-impact 是特性、在 tech-deep 是離群;版型多變在 keynote-impact 不扣、在 tech-deep 從嚴),「投影片風格」記錄的偏離視為合規,不重複扣分。

**Layout 與版型**

- 版型是否出自 `layouts.md` 詞彙表;同 section 同類內容是否沿用同一版型,跨頁重點位置是否固定
- 切格是否有理由:內容是一個整體卻被硬切成多格(整頁單一區塊本來就是合法版型),或每頁都反射性三等份 — 都算版型誤用
- grid 沒塌陷(格數 = 內容數)、格內不擁擠、文字不溢出格子;層級 3 級以內,重點分得出來
- 一頁一重點:能不能一句話說出這頁要幹什麼;說不出來就是該拆。標題就是這句話 —— 標題要用逗號串兩件事才寫得完,代表這頁有兩個重點(同時計入第 14 項)
- 圖是主角時有沒有給夠大的格

**視覺引導(動線)**

- 開頁第一眼落在哪?是不是這頁的重點?第一眼被次要元素(裝飾、過大的次要圖、強調濫用)搶走就是動線失敗
- 閱讀順序能否一次走完:左→右、上→下與內容邏輯(先→後、因→果)一致,不需要跳來跳去回頭找
- 有圖的頁:連接線是否**順著動線引導視覺** — 線的方向把眼睛帶向重點,而不是拉回頭或指向頁面外;圖文之間的對應關係一眼能接上
- 判斷方法:對每頁說出「眼睛從 A 進 → 依序看 B、C → 停在 D」;說不出來或與講述順序相反,就是要修

**分層(前景 / 背景)**

- **前景可讀性**(最重要):正文與標題疊在背景最濃處還讀得清嗎?讀不清就是 `--bg-opacity` 太高或素材太花 — 指得出是哪一頁的哪一塊
- **背景沒搶第一眼**:開頁第一眼落在背景圖案上就是失敗;圖案應走邊角、中央讓給內容
- **背景不承載資訊**:背景裡不該有要讀的字或圖表
- **換得有語意**:用到的每一套背景(預設 / `bg-2` / `bg-3` / scoped 覆寫)都要對得上 `topic.md`「投影片分層」寫的用途;**逐頁亂換、或用了超過分層章節定義的套數**就是失控,列出哪幾頁
- **該關的關了**:圖表頁、截圖頁、密集表格頁應為 `bg-none`(基底另有規定則從基底)
- **角標**:每頁的固定角標存在且沒被背景吃掉;深色頁(divider)的角標對比夠不夠;不該有角標的頁有沒有清掉
- **資產齊全**:theme.css 與 scoped style 引用的背景/角標檔都存在(腳本已列);缺檔時 build 不報錯,但整頁只剩底色 — 這是**阻斷項**
- `topic.md` 沒有「投影片分層」章節時,本面向只檢查前景可讀性與資產存在性,並在報告建議補跑 `/topic-design` 定分層

**配色統一**

- 色值只住在 `theme.css` tokens;deck 內寫死色值(腳本已列)逐條確認是特例還是失控
- 強調色只在強調時出現(一頁最多一處);語意跨頁固定(紅=問題不能中途換義)
- 對比:正文對背景要看得清;符合 `topic.md` 的 `slide-style` — 偏離要指出哪一頁偏到哪去

**文字規範遵循**(基準 = `topic.md` 的「文字規範」;它是唯一選單,級別的實際大小以 theme.css 為準)

- **可區分性**:標題與內文、條列各點之間讀起來分得開 — 行距與字級落差足夠,沒有字擠成一團難以掃讀的區塊;grid 格內文字沒有因塞太多而變成密文
- **出自規範**:每頁用到的字級、強調方式(粗體/底線/強調色)、列表符號都在文字規範的選單裡且用在規範說的情境;規範外的用法逐條列出(哪頁、什麼寫法、規範裡沒有)
- **同情境一致**:同類內容跨頁同字級、同強調、同符號(同是要點就不該一頁圓點一頁編號、同是關鍵術語就不該一頁粗體一頁底線);出現差異時檢查有沒有明確理由(刻意對比等),沒有理由的差異就是失控
- 強調是否過量:一頁裡粗體/底線/強調色加起來蓋掉太多正文,等於沒有強調

**圖形(有圖的頁才評)** — 準則見 `diagrams.md`,扣分線照該表

- **連接線轉折 ≤2 折**:3 折以上就扣分;腳本已列候選,開檔確認哪些是真的連接線。交叉線、流向、標籤距離、節點數同表
- **實際渲染可讀性**:圖形字級是名目值,嵌入格縮放後還讀得到才算數 — 這只能在 dist 頁面上看
- 目視存疑時用 `/svg-layout` 的 lint 取得量化證據(標籤溢出幾 px、端點間隙幾 px、幾折);報告要指得出數字,這裡是數字的來源
- 圖形**類型**與設計文件規劃一致(**畫法不比對** — 座標與節點擺放是實作自主權,只要沒違反紀律就不算問題);圖上元件名稱與頁面文字、備註同名;風格傾向符合 `style-base`(見 `diagrams.md` 的基底對照表)
- **截圖加註圖**:base64 是否內嵌(外連路徑在 `<img>` 下不載入,整張空白就是這個);標記與頁面圖例編號**一一對應**且順序 = 動線順序;標記 ≤5、色值出自 tokens;縮放後被指的 UI 與編號仍看得清(折數規則對此類圖不適用)

**備註品質**

- 每頁有備註;內容是**提醒**(要點、措辭、數字、時間)而非逐字稿或情境描述;段落首尾有「銜接:」「交棒:」
- 備註與頁面內容對得上(備註講 A 頁面寫 B 就是不一致)

**用語與概念一致**

- 同一概念全場同名(投影片、備註、圖形標籤都算);中英夾雜規則一致:首次全稱 + 縮寫,之後統一
- 專有名詞大小寫正確且一致;標題語法一致(全名詞短語或全結論句);數字與單位格式一致

**文案語感**(基準 = `_shared/wording.md`;**這一項不留餘地** — 命中就是命中,不看反面證據,不因風格基底而放寬)

檢查範圍:標題、副標、內文、表格文字、**圖形標籤與圖說**、**備註**。逐條抄下原句與位置(第幾頁、標題還是內文)。

- **對比翻轉句**(禁區一):同一句裡「否定 + 轉折」—— 「A,不等於 B」「是 A,不是 B」「不是 A,而是 B」「不只是 A,更是 B」「與其 A,不如 B」「不在 A,而在 B」「A 很重要,但 B 更重要」「看似 A,其實 B」、破折號翻轉「A —— 其實是 B」,以及英文的 "Not X, but Y" / "It's not about X, it's about Y"。**投影片上的每一句都應該直接講事情**;要做對比是版面的工作(兩欄、表格、✓/✗、前後兩頁),不是句子的工作
- **人稱代名詞**(禁區二):投影片前景文字出現「我」「我們」「你」「你們」「大家」「各位」—— 台下已經知道誰在講、講給誰聽,寫上去不帶資訊。備註出現口播人稱(「我要跟大家說…」)算備註逐字稿化,兩處都扣
- **空泛詞**(禁區三):賦能、助力、一站式、全方位、無縫整合、極致、打造、閉環、顛覆、革命性
- **標題不是重點主軸**(禁區四):**逐頁看標題,三條各自算一次命中** —— ①標題用逗號把兩件事串在一起(專有名詞內含標點與必要的並列頓號除外);②標題在描述這頁要「介紹/說明/比較/分析」什麼,而不是說出這頁的結論或要回答的問題;③標題塞進前提、範圍限定、方法或步驟。無資訊標題(概述、總結、背景、簡介、關於 X)算第②條。命中時在報告寫明是哪一條、並指出這頁真正的重點是什麼(逗號串兩件事的另外註明「建議拆頁」還是「砍掉一半」)
- **膨脹副詞與贅語**:真正的、其實、關鍵在於、值得注意的是 —— 刪掉不影響意思的字
- **例外不扣**:引用他人原話(有引號與出處)、程式碼與截圖裡的原文、專有名詞,以及 `topic.md`「文字規範」的「文案語感例外」明列、使用者拍板的措辭。例外要在報告寫明是哪一條
- 誤判要排除:「是不是」「不是…就是…」這類並列不是翻轉句;正則命中但開檔確認為誤判的,在報告標「已排除」

**AI 感(具體訊號,不是感覺)**

- 樣板骨架:每頁都「標題 + 三張等寬卡片」,內容換了結構沒換;`card` 類別濫用
- 強迫對稱:什麼都湊成三點、每點字數幾乎一樣長;無意義裝飾與 emoji 項目符號
- 假數據:圖表軸沒單位、數字是 100/200/300、趨勢線沒有來源
- 沒有講者痕跡:沒有真實專案名、實際數字、踩過的坑、取捨理由

反面證據(有人味):具體數字與專案名、明說的取捨、不對稱但有理由的版面、承認的失敗。判斷**版面與內容層面**的 AI 感時**先找反面證據**,找不到才扣分 —— 但**文案語感的四個禁區不適用這條**,句型、人稱與標題寫法是硬性規範,有反面證據也照扣。

## 十四項指標(每項 0–5,總分 70)

| # | 指標 | 5 分 | 3 分 | 1 分 |
|---|---|---|---|---|
| 1 | **主軸貼合度** | 偏題 ≤10%,每段都說得出對核心訊息的貢獻 | 偏題 ≤25%,或有 1 段貢獻說不清 | 偏題 >35%,或核心訊息在投影片與備註中從未出現 |
| 2 | **結構完整度** | 開場鉤子、核心訊息明說、收束與行動呼籲三者都在 | 缺其中一項 | 缺兩項以上,或結尾停在最後一張技術頁 |
| 3 | **銜接自然度** | 無突兀接縫,可接受 ≤1 | 突兀 1–2 處 | 突兀 ≥3 處,或有段落接縫完全沒有理由 |
| 4 | **先備知識鋪陳** | 概念都在使用前被解釋,`depends-on` 與 order 一致 | 有 1 個概念用在解釋之前 | 順序倒置,或依賴 rejected 段落 |
| 5 | **備註完備度** | 每頁有提醒式備註,首尾銜接/交棒齊全,備註與頁面一致 | 1–2 頁缺備註、備註逐字稿化或出現口播人稱 | 大面積無備註,或備註與頁面講的是兩回事 |
| 6 | **節奏與時間帳** | est 合計佔總時長 90–95%;每頁 20–180 秒 | est 佔比略出界,或 1–2 段翻頁過快/停留過久 | est 超出總時長,或多段節奏出界 |
| 7 | **認知負荷曲線** | 單一峰值落在中段且峰後有喘息 | 峰值偏後段,或峰後無喘息 | 多個連續峰值,或峰值全在最後 20% |
| 8 | **版面、配色與分層一致度** | 版型出自詞彙表且跨頁收斂;色值只住 tokens 且語意固定;背景套數與換背景的頁面都對得上「投影片分層」、前景在每頁都讀得清;無溢出塌陷 | 2–3 頁版面、用色或背景離群 | 每頁自成一套、寫死色值失控、背景逐頁亂換或壓過前景,或有溢出/對比不足 |
| 9 | **用語與概念一致度** | 同概念全場同名(含圖形標籤與備註),縮寫規則一致 | 有 1–2 個概念換過名字 | 關鍵概念三種以上叫法,聽眾會以為是不同東西 |
| 10 | **去 AI 感/原創度**(版面與內容層面;文案句型歸第 14 項) | 版面隨內容變化,有真實數字、專案名與取捨 | 有樣板痕跡但內容具體 | 樣板骨架 + 強迫三點對稱 + 假數據,看不出誰講的 |
| 11 | **圖解可讀性** | 所有連接線 ≤2 折、無交叉、流向單一、標籤貼線、節點 ≤7、縮放後讀得到 | 有 1–2 條 3 折線,或少量交叉 | 有 ≥4 折線、線條交叉成網、看不出流向,或縮放後文字不可讀 |
| 12 | **視覺引導** | 每頁第一眼落在重點,動線一次走完且與內容邏輯一致,連接線順著動線,背景退到後面不參與動線 | 2–3 頁動線要回頭找,或第一眼被次要元素(含背景圖案)搶走 | 多數頁說不出動線,資訊量大但抓不到重點 |
| 13 | **文字規範遵循度** | 字級/強調/列表符號全出自文字規範且同情境一致;標題內文行距分明 | 2–3 處規範外用法或無理由的不一致 | 文字技法各頁自創、同類內容寫法不一,或多頁文字擠成一團難以掃讀 |
| 14 | **文案語感**(基準 `wording.md`,不留餘地) | 全場 0 句對比翻轉句、0 個人稱代名詞、0 個空泛詞;每一頁的標題都是一句話講完的重點主軸 | 命中 1–2 句(且都不在標題/副標),其餘文案直述 | 命中 ≥5 句,或翻轉句/人稱/描述式標題出現在標題與副標 |

第 11 項只在有圖形時計分;整場沒有圖就標「不適用」,總分改除以 65。`topic.md` 沒有「文字規範」章節時,第 13 項改以 theme.css 既有字級與全簡報實際用法的一致性評分,並在報告建議補跑 `/topic-design` 定規範。

**第 14 項的計分是硬規則**(命中數 = 確認為真的句數,排除誤判與已登記的例外):

| 確認命中 | 第 14 項上限 |
|---|---|
| 0 | 5 |
| 1–2(都不在標題/副標) | 3 |
| 3–4,或任一句在標題/副標 | 2 |
| ≥5 | 1 |

同一句同時犯翻轉句與人稱算兩條;標題同時犯「逗號串兩件事」與「描述而非結論」也算兩條。**標題與副標命中要另外連動**:第 10 項(去 AI 感)上限一併下修到 3 —— 標題是全頁第一眼,套語出現在那裡就是整份簡報的語感問題。

**符合度** = 總分 ÷ 70(無圖時 ÷ 65)。判定帶:

- **≥90%** 可以上台
- **75–89%** 小修即可上台(列出修哪幾處)
- **60–74%** 有結構問題,先修再排練
- **<60%** 回頭重整段落設計

**阻斷項**(命中就先修,分數再高也不放行):腳本有任何 ✗、先備知識順序倒置、頁面引用的圖檔不存在、**theme.css 或 scoped style 引用的背景/角標檔不存在**、任何外部資源(離線就掛)、核心訊息在投影片與備註中從未出現、文字溢出格子或畫面、**正文被背景蓋到讀不清**、build 失敗、**標題或副標出現對比翻轉句或人稱代名詞**(逐句列出頁碼與原句,導向 `/page-adjust` 改成直述句)。連接線轉折只計入第 11 項扣分,不列阻斷(腳本用 △ 標示)。

**流程阻斷**:有任何一頁沒開過就不准給第 5/8/9/10/11/12/13/14 項分數 — 改寫「未評(第 XX 頁未檢視)」,不要用腳本表格推測;審過期產物同罪,先 build 再看。

## 輸出格式

報告寫入 `review/review-<YYYY-MM-DD>-<序號>.md`(當日已有報告時序號 +1,不覆蓋舊報告),開頭加 metadata:

```yaml
---
id: review-<YYYY-MM-DD>-<序號>
type: review
title: <talk-slug>-review
description: <一句話:本次審查的範圍與結論,40 字內>
created: <YYYY-MM-DD>
scope: full            # full | section-XX(局部審查)
score: <N>/70          # 無圖時 /65
verdict: <判定帶,如:小修即可上台>
---
```

報告內文結構如下;寫完後在**對話中只給摘要**(符合度、判定帶、阻斷項、前三優先修正)與報告路徑:

```markdown
## 檢查範圍
(讀了哪些檔案、幾段幾頁幾張圖;**是否重 build、逐頁開了哪幾頁、用瀏覽器還是讀原始碼**;局部審查要標明)

## 機械檢查
(腳本結果摘要:✗ 逐條列、△ 擇要;無 ✗ 就一句話帶過)
(層級紀律:topic.md / section 文件有沒有寫死視覺數值或 class 名、與 theme.css 是否漂移;無則一句話帶過)

## 逐段評述
| Section | 分鐘 | 分類 | 對核心訊息的貢獻 / 問題 |
|---|---|---|---|
(分類 = 貼題 / 支援 / 呼吸點 / 偏題;偏題與呼吸點寫明理由)
偏題比例:X 分 / Y 分 = Z%

## 逐頁檢視(每一頁都要有一列,✓ 無問題 / △ 待確認 / ✗ 要修)
| 頁 | Section | 版型 | 背景 | Layout | 動線 | 配色 | 文字 | 語感 | 圖形 | 備註 | 用語 | AI感 | 具體問題(指得出元素、色值或線條座標) |
|---|---|---|---|---|---|---|---|---|---|---|---|---|---|
(圖形欄:無圖寫 -;有圖寫最大折數,如 `2折 ✓` / `5折 ✗`。背景欄:寫這頁實際的背景類別與判定,如 `預設 ✓` / `bg-none ✓` / `bg-2 △`。動線欄 = 視覺引導;文字欄 = 文字規範遵循;**語感欄 = 文案語感**,無命中寫 ✓、有命中寫 `翻轉句 ✗` / `人稱 ✗` / `空泛詞 ✗` / `標題 ✗` 並在具體問題欄抄原句)

全簡報視覺一致性:版型使用分布、tokens 之外的色值、跨頁版面語彙是否共用一套(引腳本表當證據);**分層總結**(用了幾套背景、各出現在哪些頁、是否對得上「投影片分層」的語意、前景可讀性有問題的頁);文字規範遵循總結(規範外用法清單、同情境不一致清單 — 各附頁碼)

## 文案語感(禁用句型與人稱)
| 頁 | 位置 | 原句 | 命中哪一條 | 建議改法 |
|---|---|---|---|---|
(位置 = 標題 / 副標 / 內文 / 表格 / 圖形標籤 / 備註。**逐條抄原句**,不要只寫「有 AI 腔」;建議改法寫成直述句或「對比移到版面」的具體做法;標題命中則寫出改寫方向或「拆成兩頁」。腳本列出但確認為誤判的另起一行標「已排除」並寫理由。無命中就寫「無 — 全場文案皆為直述句」)
確認命中 N 條(標題/副標 M 條)→ 第 14 項 X 分(標題/副標命中時第 10 項一併封頂 3 分)

## 接縫檢查
- 段落接縫:自然 N 處;可接受/突兀逐條列(哪兩段之間、為什麼、怎麼修;銜接/交棒備註是否對上)

## 峰值地圖
(難度序列,如 section-01 低 → 02 高(峰)→ 03 中;峰值位置、是否連續、峰後有無喘息)

## 指標符合度

|---|---|---|---|

## 阻斷項
(命中的逐條列;無則寫「無」)

## 修正建議
(依優先序;每條標明用哪個命令、動哪個檔案、預期換來哪一項指標的提升)
```

## 紀律

- **證據優先**:每個扣分都要指得出檔案、段落、頁碼,視覺問題還要指得出元素或色值(「第 04 頁 #00ff88 不在 tokens 且不是強調」勝過「配色不統一」);講不出證據的扣分不要寫
- **沒看過不評**:逐頁檢視表缺哪一頁就寫「未檢視」,不要用腳本表格或原始碼推測那頁渲染起來長什麼樣
- **AI 感要留餘地,文案語感不留**:版面與內容的 AI 感先找反面證據(真實數字、專案名、取捨),找不到才扣分;風格偏好是使用者的,`topic.md` 允許的風格與選定的風格基底特性(見 styles.md 各基底 review 提示)不算 AI 感。但 `wording.md` 的四個禁區(對比翻轉句、人稱代名詞、空泛詞、標題寫成描述或用逗號串兩件事)是硬性規範 —— 不因風格基底、不因反面證據、不因「這句寫得漂亮」而放過;唯一的免扣是引用原話、程式碼截圖原文,或 `topic.md`「文案語感例外」明列的使用者決定
- **不代寫但要給方向**:文案語感命中的句子,報告寫「原句 + 命中哪一條 + 往哪個方向改」(如「對比移到兩欄」),不要在報告裡把整頁文案重寫一遍
- **不腦補主軸**:核心訊息以 `docs/topic.md` 為準;覺得主軸本身有問題,寫進建議讓使用者決定,不要自己換一個主軸來評分
- **不重寫內容**:報告寫「哪裡不對、為什麼、建議往哪個方向」,不要在報告裡代寫頁面、備註或 SVG
- 使用者反駁某項評分時,重新檢視證據:證據不足就下修結論,證據充足就把證據攤開,不要為了順從而改分
