# /review — 演講整體審查

先讀取 `../_shared/conventions.md`,遵守其中所有文檔慣例(metadata、頁碼同步、投影片規格)。

## 唯讀原則(不可違反)

本命令**只讀不寫**:不產出任何文檔、不修改任何檔案、不更新 metadata 的 `updated`、不「順手修一下」。
所有結論都以對話輸出。使用者要動手修時,導向對應命令:單頁 → `/page-adjust`、段落設計 → `/section-discuss`、講稿與 SVG → `/section-impl`、主軸或時間分配 → `/topic-design`。

## 範圍

- 無參數 → **全場審查**
- 參數是段落 id 或編號(`section-02`、`02`)→ **局部審查**:只審該段與其 `depends-on`、以及它與前後段的接縫;指標照算但在報告標明「局部,總分僅供該段參考」

## 前置

1. 執行機械檢查腳本(唯讀):

```
node <本 skill 目錄>/scripts/scan-coherence.mjs [專案根目錄,預設 .]
```

腳本交叉比對頁碼五處同步、段落覆蓋、先備知識順序、節奏(講稿字數對時)、銜接標記,並輸出**各頁投影片文字摘要**。

2. 有「frontmatter 格式不合規」時**先停下**:清單欄位讀不到值,後面的比對全部不可信。請使用者(或經同意)改回行內陣列 `[a, b]` 再重跑。
3. 讀取 `docs/topic.md`(核心訊息、聽眾輪廓、投影片風格是所有判斷的基準)、全部非 rejected 的 `docs/section-*.md`、`talk/scripts.md` 全文。
4. SVG **不逐檔開**:先用腳本的頁面文字摘要比對講稿說法;只有摘要顯示可疑(文字與講稿說法不符、無 `<text>`、版面語彙有疑慮)的頁面才開原檔。rejected 段落不讀。

## 判斷準則

### 偏題怎麼算

逐段標記四類,**偏題不是罪,量太多才是**:

- **貼題**:直接推進核心訊息
- **支援**:不直接推進但為後段鋪路(先備知識、動機、反例)
- **呼吸點**:刻意的幽默、故事、閒聊 — 服務節奏,**不計入偏題**
- **偏題**:對核心訊息無貢獻,也不服務節奏

偏題比例 = 偏題段落的 `est-minutes` 合計 ÷ 總時長。呼吸點超過 15% 時另計為節奏問題,不算偏題。

### 銜接怎麼評

每個接縫(段落接縫 = 段數 − 1;頁面接縫 = 頁數 − 1)評三級:

- **自然**:上一段/頁的結尾為下一個開場提供理由(問題被提出 → 下一段回答;概念被建立 → 下一頁使用)
- **可接受**:順序合理但沒有明說理由,聽眾要自己補
- **突兀**:主題硬切、需要尚未鋪陳的概念、或風格語彙突變

只列**突兀**與**可接受**的接縫並寫明理由;自然的只給數量。

### 峰值怎麼找

以「每分鐘新概念數」估段落難度(新概念 = 聽眾輪廓的「未知」清單裡的詞、或本段首次出現且需要解釋的術語)。峰值 = 明顯高於相鄰段落者。判斷三件事:

1. 峰值位置 — 落在演講 30–70% 處最好;全擠在最後 20%(疲勞區)最糟
2. 峰值是否連續 — 連續兩段高峰等於讓聽眾一路掉線
3. 峰後有沒有喘息 — 複習頁、圖解、呼吸點

## 七項指標(每項 0–5,總分 35)

| # | 指標 | 5 分 | 3 分 | 1 分 |
|---|---|---|---|---|
| 1 | **主軸貼合度** | 偏題 ≤10%,每段都說得出對核心訊息的貢獻 | 偏題 ≤25%,或有 1 段貢獻說不清 | 偏題 >35%,或核心訊息本身在講稿裡從未出現 |
| 2 | **結構完整度** | 開場鉤子、核心訊息明說、收束與行動呼籲三者都在 | 缺其中一項 | 缺兩項以上,或結尾停在最後一張技術頁 |
| 3 | **銜接自然度** | 無突兀接縫,可接受 ≤1 | 突兀 1–2 處 | 突兀 ≥3 處,或有段落接縫完全沒有理由 |
| 4 | **先備知識鋪陳** | 概念都在使用前被解釋,`depends-on` 與 order 一致 | 有 1 個概念用在解釋之前 | 順序倒置,或依賴 rejected 段落 |
| 5 | **講稿↔投影片一致度** | 無孤兒頁/幽靈標記;頁面文字與講稿說法、數字一致 | 有 1–2 處措辭或數字不一致 | 有孤兒頁,或投影片講 A 講稿講 B |
| 6 | **節奏與時間帳** | est 合計佔總時長 90–95%;講稿對時偏差 ≤15%;每頁 20–180 秒 | 偏差 ≤30%,或 1–2 段翻頁過快/停留過久 | 超出總時長,或講稿逐字照講會超時 |
| 7 | **認知負荷曲線** | 單一峰值落在中段且峰後有喘息 | 峰值偏後段,或峰後無喘息 | 多個連續峰值,或峰值全在最後 20% |

**符合度** = 總分 ÷ 35。判定帶:

- **≥90%** 可以上台
- **75–89%** 小修即可上台(列出修哪幾處)
- **60–74%** 有結構問題,先修再排練
- **<60%** 回頭重整段落設計

**阻斷項**(命中就先修,分數再高也不放行):腳本有任何 ✗、先備知識順序倒置、孤兒頁、講稿對時超過總時長、核心訊息在講稿中從未出現。

## 輸出格式(對話,不落檔)

```markdown
## 檢查範圍
(讀了哪些檔案、幾段幾頁、講稿字數;局部審查要標明)

## 機械檢查
(腳本結果摘要:✗ 逐條列、△ 擇要;無 ✗ 就一句話帶過)

## 逐段評述
| Section | 分鐘 | 分類 | 對核心訊息的貢獻 / 問題 |
|---|---|---|---|
(分類 = 貼題 / 支援 / 呼吸點 / 偏題;偏題與呼吸點寫明理由)
偏題比例:X 分 / Y 分 = Z%

## 接縫檢查
- 段落接縫:自然 N 處;可接受/突兀逐條列(哪兩段之間、為什麼、怎麼修)
- 頁面接縫:自然 N 處;可接受/突兀逐條列(哪兩頁之間、為什麼)

## 峰值地圖
(難度序列,如 section-01 低 → 02 高(峰)→ 03 中;峰值位置、是否連續、峰後有無喘息)

## 指標符合度
| # | 指標 | 分數 | 依據 |
|---|---|---|---|
總分 N/35 = XX% → <判定帶>

## 阻斷項
(命中的逐條列;無則寫「無」)

## 修正建議
(依優先序;每條標明用哪個命令、動哪個檔案、預期換來哪一項指標的提升)
```

## 紀律

- **證據優先**:每個扣分都要指得出檔案、段落或頁碼;講不出證據的扣分不要寫
- **不腦補主軸**:核心訊息以 `docs/topic.md` 為準;覺得主軸本身有問題,寫進建議讓使用者決定,不要自己換一個主軸來評分
- **不重寫內容**:報告寫「哪裡不對、為什麼、建議往哪個方向」,不要在報告裡代寫講稿或 SVG
- 使用者反駁某項評分時,重新檢視證據:證據不足就下修結論,證據充足就把證據攤開,不要為了順從而改分
