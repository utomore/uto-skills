# /topic-design — 演講主軸設計

先讀取 `../_shared/conventions.md`、`../_shared/styles.md`、`../_shared/layers.md` 與 `../_shared/wording.md`,遵守所有文檔慣例(資料夾結構、命名、metadata、Marp 建置)、風格基底詞彙、分層詞彙與**文案語感規範**(禁用句型與人稱指稱 —— 主題、副標、大綱的措辭一樣受它約束)。

## 目標

與使用者討論出演講的**真正主軸**,產出燈塔文件 `docs/topic.md`、資料夾結構與 Marp 鷹架(`talk/src/`)、各段落佔位文檔。**在主軸與段落切分明確之前,禁止產出任何文件。**

## 顆粒度(本階段的核心紀律)

本命令是三層階梯的 **Level 1**:寫到「核心訊息、段落切分、視覺規範的**語意**」為止。

- 視覺規範定的是**語意與數量** —— 強調有哪幾種、各代表什麼;背景幾套、各對應演講的什麼結構;哪個字級用在哪個情境。
- **絕對禁止**把 CSS 數值(px、色碼、`--bg-opacity` 的值)、class 名或槽位編號寫進 `docs/topic.md`。那些的唯一真相是 `talk/src/theme.css`,兩份數值必然漂移。
- 本命令**會寫 theme.css**(它是全簡報共用的鷹架,必須在 Level 1 就位),但寫進去的是**起始值**;之後 `/section-impl` 依真實頁面調整數值,不必回頭改 topic.md。
- 逐頁怎麼排、哪一頁用哪個背景類別、圖怎麼畫,都屬於 `/section-design`(Level 2)與 `/section-impl`(Level 3),本階段不預先指定。

## 模式判斷

- `docs/topic.md` 不存在 → **初始模式**:完整訪談後從零產出
- `docs/topic.md` 已存在 → **更新模式**:先讀取現有內容與各 section 狀態,針對要調整的部分訪談;主軸變動會牽動所有 section,必須列出受影響段落並取得使用者同意後才動手;`slide-style` 變動要同步 `talk/src/theme.css` 的 tokens;「投影片分層」的**語意變動**(增減背景套數、換某一套的用途)要同步改 topic.md 該章節、theme.css 的分層 tokens 與 `talk/assets/` 的背景資產,並列出原本寫了 `bg-*` 類別的頁面確認語意還對得上,**已有實作頁面時重 build 抽看最文字密與最空的頁面**;「文字規範」變動要列出已實作頁面中受影響的用法,提醒使用者跑 `/page-adjust` 跟進;`style-base` 換基底是**全簡報級改動**(版面、配色、文字規範、圖形風格全部重看),必須列出已實作段落並確認使用者理解影響範圍

**純數值調整不走本命令**:使用者只是覺得「背景太濃」「字太小」時,那是 theme.css tokens 的調整 —— 導向 `/page-adjust`(單頁特例或全簡報 tokens 微調)。topic.md 沒有記錄這些數值,不需要更新。

## 流程

### 1. 訪談階段(核心,不可跳過)

分多輪詢問使用者,直到主軸完全明確。**不確定就再問,禁止自行腦補。** 選擇題用 AskUserQuestion,開放式問題直接問。必須涵蓋:

1. **時長**:整場演講幾分鐘?含不含 Q&A?
2. **領域與題材**:講什麼領域?使用者手上有什麼素材(專案經驗、研究、工具)?
3. **聽眾範圍**:誰會來聽?人數規模?聽眾的技術能力(beginner / intermediate / advanced / mixed)與先備知識?
4. **會議類型**:deep-tech(深度技術分享)、intro(啟蒙/科普)、workshop(工作坊)、lightning(閃電秀)、keynote(主題演講)、internal(內部分享)、lecture(教學課程)— 類型決定深度與節奏
5. **講者先備知識**:使用者對題材的熟悉度、想避開或想突顯的部分
6. **風格基底與偏好**(**文案語感不在訪談範圍** —— 禁用句型與人稱指稱是全流程固定的硬性禁區,直接套 `wording.md`,只有使用者主動要求破例時才記進「文案語感例外」):先依會議類型從 `styles.md` 推薦風格基底(tech-deep / keynote-impact / intro-friendly / workshop-guide / exec-brief),用 AskUserQuestion 讓使用者選定或改選 — **基底定案後,版面、配色、分層、文字規範、圖形風格、節奏都有了預設方向**;再細調視覺偏好(深色/淺色、色彩傾向)、演講風格(敘事型、示範型、論證型)與文字技法偏好(強調習慣用粗體還是色彩、列表符號偏好)— 細調結果與偏離基底之處都會寫死進「投影片風格」與「文字規範」
7. **前景/背景分層**(依 `layers.md`,基底的「分層」節是起點):先講清楚兩層的分工 —— 背景層是裝飾(色塊、漸層、品牌圖樣),前景層是標題、內文、圖形與固定角標,**要聽眾讀的東西一律在前景**。本階段只問到**語意與數量**,強度與逐頁類別留給 `/section-impl`:
   - **要不要背景?** 用 AskUserQuestion 給「不要(純色底)/ 要」;`none` 是完全合法的答案,資訊密度高或要印出來時反而是最佳解
   - **素材從哪來?**(要背景才問)三選一:①**使用者提供背景圖片**(品牌背景、照片 — 請他給檔案路徑,存進 `talk/assets/bg-<slug>.<ext>`);②**跟你討論風格現做**(問風格關鍵字:柔和有機 / 幾何弧線 / 格線科技 / 單側色帶 / 其他;可直接拿本 skill `assets/backgrounds/` 的三張範本當選項給他挑,或依關鍵字用 CSS 漸層與新畫的 SVG 現做);③**先用 CSS 漸層**(免資產,改色最快)
   - **要幾套?各代表什麼?** 問全場一套夠不夠,還是封面/轉場、某個段落、demo 頁要換一套。**問的是演講結構上的區隔**(「demo 那段想跟前面拉開嗎」),不是問使用者要填哪個 CSS 槽位 —— 槽位怎麼對應由本命令產出時決定。每一套都要說得出用在哪一組頁面,寫進「投影片分層」;超過三套要回頭確認是設計還是失控
   - **哪些頁型不要背景?** 問使用者的直覺(通常是圖表頁、截圖頁、密集表格頁);記語意即可,對應到哪個類別是實作的事
   - **固定角標**:每頁要不要放 logo / 活動名 / 講者 handle?要就請使用者提供圖檔(存 `talk/assets/logo.<ext>`),定位置(預設左下,頁碼在右下)
   - **不要在這裡定強度**:`--bg-opacity` 的最終值要有真實頁面才判斷得出來,本階段只在 theme.css 填 `layers.md` 建議的起始值(0.35–0.5;照片背景 0.2–0.35),驗收在第一段 `/section-impl` 完成後做
8. **輸出格式**:上台用什麼?(html 鍵盤翻頁 / pdf 備援分發 / pptx 交主辦方;可複選,記入 `outputs`)
9. **Demo 需求**:是否需要現場示範?(需要時建議 uv + python + notebook,依使用者要求可置換;demo 屬於某個 section,細節留給 `/section-design`)

每輪訪談後摘要目前已確認的內容,列出仍不明確的點繼續問。

### 2. 提出 3 組主題方案(必做)

依訪談結果提出 **3 組可選方案**,每組含:**主題、副標題、大綱(3–6 條)**,並各附一句「為什麼適合這批聽眾」。**主題與副標直接講事情** —— 不用對比翻轉句(「不是 A,而是 B」「A,不等於 B」)、不用人稱代名詞(我們/你/大家),規範見 `wording.md`;使用者自己指定的措辭照用,但要記進「投影片風格」的文案語感例外。用 AskUserQuestion 讓使用者選擇或混搭;使用者也可要求重出。選定後與使用者確認最終的主題與副標題措辭。

### 3. 段落切分方案

依選定主軸與時長提出 section 切分(含每段預估分鐘數),與使用者逐段確認名稱、目的與順序:

- 時間帳:各段 `est-minutes` 總和 ≈ 總時長,留 5–10% 緩衝
- 段落數參考:lightning(5–10 分)2–3 段;30–40 分 4–6 段;60 分以上 6–8 段
- 段落 ≠ 投影片張數:一段可以 0 頁(純口述)到多頁
- 需要 demo 時,demo 自成一段或明確掛在某段之下

### 4. 產出

全部明確並經使用者最終確認後:

1. 建立資料夾:`docs/`、`talk/src/`、`talk/assets/`(`demo/` 只在確定需要時建立)
2. 鋪設 Marp 鷹架 — 從本 skill 的 `assets/` 複製到 `talk/src/`:
   - `theme.css`:複製後**依選定的風格基底與訪談細調填 tokens 區的起始值**(色票 CSS variables 與字體 — 基底的「配色」節給方向,如 keynote-impact 高對比敢用色、exec-brief 樸素印表機友善;深色風格連 `--c-bg`/`--c-text` 對調並檢查表格、卡片底色),以及**分層 tokens**(`--bg-image` / `--bg-image-2` / `--bg-image-3` / `--bg-opacity` / `--fg-plate` / `--fg-mark-*`,把訪談定案的每一套背景填進對應槽位);版型類別區與分層機制區(`section::before`、z-index、`bg-*` 類別)**不要動**。**這裡填的是起始值** —— theme.css 是視覺數值的唯一真相,後續由 `/section-impl` 依真實頁面調整,不必回頭改 topic.md;`--bg-image` 用漸層時在上方留一行註解提醒「改色票要一併重抄漸層色碼」
   - `deck-header.md`:照抄(theme 名稱 `talk` 與 theme.css 的 `@theme` 一致);有固定角標時加一行 `footer: '![h:26](../assets/logo.svg)'`
   - `build.mjs`:照抄
   - `marprc.yml` → 複製為 `talk/src/.marprc.yml`
   - **背景資產**(選了資產檔路線才做):使用者提供的圖 → 複製進 `talk/assets/bg-<slug>.<ext>`;選用範本 → 從本 skill `assets/backgrounds/` 複製對應的 `bg-*.svg` 到 `talk/assets/` 並**把色值改成本演講的色票**;現畫的 SVG 一樣放 `talk/assets/`,規範見 `layers.md`(XML 註解不得含連續兩個減號、柔邊用 radialGradient 不用 blur)。`talk/src/` 底下**不要留第二份 .css**
3. 產出 `docs/topic.md`,frontmatter 依 conventions(含 `outputs` 與 `background`),內文固定章節:

```markdown
# <演講題目> 主軸設計

## 主軸說明
(選定的主題、副標題、一段話的核心訊息 — 聽眾走出場要記得的一件事)

## 候選方案記錄
(訪談時提出的 3 組方案與選擇理由,留檔備查)

## 聽眾輪廓
(範圍、規模、技術能力、先備知識;聽眾「已知/未知」清單)

## 講者先備知識
(講者熟悉度、需要事前補強的部分)

## 大綱與段落規劃
(選定大綱;每段一列:id、名稱、目的、預估分鐘、預估頁數範圍)
| Section | 名稱 | 目的 | 分鐘 | 頁數(預估) |
|---|---|---|---|---|

## 投影片風格
(第一行寫**風格基底**:`style-base` 的值與選擇理由;接著列出偏離基底的決定(每條「基底說 X,本演講改 Y,因為 Z」,無偏離寫「無」);再放視覺風格關鍵字與**色票的語意對照**(主色代表什麼、accent 綁哪一種意思)。**不抄色碼**:實際色值住 theme.css tokens,改色只改 theme.css)

## 投影片分層
(前景/背景分層的**語意定案**,執行期以此為準;沒有背景就第一行寫「背景:無」與理由,其餘留空。**本節不寫數值** — opacity 與色碼住 theme.css)

### 背景套數與語意(每頁背景可以不同,但每一套都要說得出用在哪)
| 套 | 素材 | 用在哪(語意) |
|---|---|---|
| 預設 | <CSS 漸層 / `bg-<slug>.svg` / 使用者提供的圖> | <如:一般內容頁> |
| 第二套 | <或「無」> | <如:封面與 divider 轉場> |
| 第三套 | <或「無」> | <如:demo 段落> |

(槽位對應由 theme.css 的 `--bg-image` / `--bg-image-2` / `--bg-image-3` 承接,頁面類別 `bg-2` / `bg-3` 由實作層對上,此處只記語意)

### 不放背景的頁型
- <哪些頁型一律關背景,如 圖表頁、截圖頁、密集表格頁 — 記語意,對應類別由實作層處理>

### 素材來源
- <使用者提供 / 範本改色 / 現畫 SVG / CSS 漸層;檔案放在 `talk/assets/` 的哪一個>

### 前景固定角標
(有:放什麼、檔案、位置、哪些頁不放(深色頁對比不足時);無:寫「無」)

## 文字規範
(**執行期唯一合法的文字技法選單** — section-impl 只能用這裡列的,不得自創;每張表都要「用在哪」明確到執行期不需再判斷。**起點是風格基底的「文字規範預設」**,依訪談細調後逐格寫死。**只寫語意不寫數值** — 每個級別實際多大由 theme.css 決定,要調大小是改 theme.css,不改本節)

### 字級(theme.css 的級別 → 使用情境)
| 級別 | 用在哪 |
|---|---|
| h1 | 封面主標、divider 段落名 |
| h2 | 每頁頁面標題(一頁一個) |
| h3 | 格內小標(grid 分組時的組名) |
| 正文 | 條列、段落文字 |
| small/caption | 來源、註解、圖說 |

### 強調方式(每種只綁一個用途,一頁 accent 最多一處)
| 寫法 | 用在哪 |
|---|---|
| `**粗體**` | <如:句中的關鍵術語首次出現> |
| `<u>底線</u>` | <如:要求聽眾記住的結論句> |
| `<span class="accent">` | <如:全頁唯一的核心數字或警示> |

### 列表符號(符號 = 語意,不同符號必須代表不同意思)
| 符號 | 語意 |
|---|---|
| `-` 圓點 | 無順序的並列要點 |
| `1.` 編號 | 有先後或優先序的步驟 |
| <其他,如 ✓/✗> | <只在明確對比語意時使用,並在此定義> |

(以上為預設值,依訪談出的風格與講者偏好調整;調整後照樣逐格寫死。行距等排版值住在 theme.css,不逐頁覆寫)

### 文案語感例外
(文案語感規範是全流程固定的硬性禁區 —— 禁對比翻轉句(「A,不等於 B」「不是 A,而是 B」…)、禁人稱代名詞(我/我們/你/你們/大家/各位)、禁空泛詞與無資訊標題,**不是偏好題,不寫進本節**。
本節只記**使用者明確指定、刻意破例**的措辭:一行一筆「哪一句、用在哪一頁/哪個標題、為什麼」。沒有就寫「無」)

## 演講風格
(敘事/示範/論證、語氣、互動方式;備註提醒的密度偏好)

## Demo 規劃
(不需要則寫「無」;需要則寫目的、形式(預設 uv + python + notebook)與掛在哪個段落)
```

4. 為每個段落產出佔位文檔 `docs/section-<編號:01>-<slug>.md`:**只放 frontmatter(status: open、slides: 0、diagrams: [])與一段「段落說明」**(目的與預計內容方向,2–3 句),其餘留給 `/section-design`
5. `topic.md` 的 `sections` 回填全部段落 id,一律行內陣列(清單欄位不用 YAML 區塊列表)

### 5. 收尾

- 摘要:產出了哪些檔案、選定的主軸、段落切分與時間分配、選定的風格基底與偏離之處、theme tokens 怎麼對應 slide-style、**分層怎麼定(幾套背景、各代表什麼、角標)**、文字規範定了哪幾種字級/強調/列表符號、**文案語感例外有沒有(沒有就說明全場照 `wording.md` 的禁區走)**
- 有背景時明說:**tokens 填的是起始值,強度驗收在第一段 `/section-impl` 完成、有真實頁面之後做** —— 本階段沒有內容頁可看,不做前景可讀性驗收
- 說明 `docs/topic.md` 是演講燈塔,之後 `/section-design` 逐段規劃內容與圖形、`/section-impl` 實作 Marp 頁面與圖形 SVG、`/page-adjust` 微調單頁、`/review` 上台前做整體審查
- 建議使用者從 `order: 1` 的段落開始執行 `/section-design`
