## 2. 共用簽名(abstract 的候選)
- `verify` 出現在 auth/E001-remember-device、auth/F001-token-refresh → 抽成 abstract 的候選
- `rotate` 出現在 auth/F001-token-refresh、billing/F001-charge → 抽成 abstract 的候選
- `charge` 出現在 billing/F001-charge、global/G-F001-checkout → 抽成 abstract 的候選

## 3. 建議的新樹
- 階段 (沒有階段)
  - auth/E001-remember-device → `devflow claim feature <slug>`(F 與 E 在新樹裡都是 feature;不擋交付的寫進 Features 表的階段欄)
- 階段 S1
  - auth/F001-token-refresh → `devflow claim feature <slug>`(F 與 E 在新樹裡都是 feature;不擋交付的寫進 Features 表的階段欄)
- 階段 S2
  - billing/F001-charge → `devflow claim feature <slug>`(F 與 E 在新樹裡都是 feature;不擋交付的寫進 Features 表的階段欄)
  - global/G-F001-checkout → `devflow claim feature <slug>`(F 與 E 在新樹裡都是 feature;不擋交付的寫進 Features 表的階段欄)
- 一份舊文檔不必然對一份新 feature:同一條使用者路徑上的幾份合成一條,共用的那幾個 step 抽成 abstract。

## 4. law 草稿
### auth/E001-remember-device
- LAW-1 [<種類>] 記住的裝置在 30 天內不再要求驗證
  - forall d in DeviceId
  - given <需形式化:無>
  - |- <需形式化:講不清楚,要看實作>
### auth/F001-token-refresh
- LAW-1 [<種類>] rotate 成功後,舊 TokenId 立刻失效
  - forall t in TokenId
  - given <需形式化:rotate(t) 回傳成功>
  - |- verify(t) == false
- LAW-2 [<種類>] rotate 不改變別的 token 的可用性
  - forall u in TokenId
  - given <需形式化:無>
  - |- <需形式化:呼叫前後 verify(u) 相同>
### billing/F001-charge
- LAW-1 [<種類>] 負金額收不成
  - forall a in Cents
  - given a < 0
  - |- charge(a) == false
